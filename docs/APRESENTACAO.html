v1.1.0-dev

Sino de Notificação Redesenhado

❌ Antes
  • Fundo transparente, sem delimitação visual
  • Efeito pulsante reaparecia a cada reload
  • Pseudo-elemento ::before interceptava cliques
  • Nome do usuário antes do sino
✅ Depois
  • Círculo cinza igual ao avatar do usuário (50×50px)
  • Efeito persiste via localStorage — só volta com notificações novas
  • pointer-events: none no pseudo-elemento
  • Nome do usuário posicionado após o sino

Lógica de persistência do efeito

Salva em localStorage['notif_dismissed_at_count'] o número de não lidas no momento em que o usuário abre o painel. O efeito (pulso + balão) só exibe se notificações atuais > valor salvo — desaparece até chegarem notificações genuinamente novas.

v1.1.0-dev

Exclusão Inteligente de Participantes

❌ Antes
  • Bloqueava exclusão se havia reservas vinculadas
  • Sem informação do motivo ao usuário
  • Admin ficava sem opção
✅ Depois
  • Frontend consulta GET /check_dependencies antes de excluir
  • SweetAlert2 mostra impacto detalhado (chamados, reservas)
  • Admin confirma e exclusão em cascata acontece em transação
  • Chamados excluídos, reservas limpas, FK nulificadas
Participant.transaction do
  Chamado.where(solicitante_id: id).destroy_all
  Reservation.where(solicitante_id: id).destroy_all
  Reservation.where(responsavel_id: id).update_all(responsavel_id: nil)
  participant.reservations.clear
  participant.destroy!
end

Período de Exibição & Segmentação por Empresa

📅

Período de exibição

Campos Exibir a partir de e Exibir até (datetime). Deixar em branco = sem restrição. Scope in_period filtra automaticamente.

Segmentação por empresa

Checkboxes para cada empresa cadastrada. Sem seleção = todos os usuários. Com seleção = apenas usuários daquela empresa.

Segmentação — UX dos Cards de Empresa

🔍

Barra de pesquisa em tempo real

Expiração Automática de Anúncios

def self.expire_passed!
  where(active: true)
    .where.not(ends_at: nil)
    .where("ends_at < ?", Time.current)
    .update_all(active: false)
end
Onde é chamado Quando ocorre
AnnouncementsController#indexAdmin acessa a listagem de anúncios
shared/_announcement_modalQualquer página carregada por usuário logado
shared/_login_announcementTela de login (acesso público)
🔄

Re-ativação manual

Admin edita o anúncio, define nova data futura (ou remove a data) e marca como Ativo. O sistema volta a exibi-lo normalmente — não há bloqueio permanente.
